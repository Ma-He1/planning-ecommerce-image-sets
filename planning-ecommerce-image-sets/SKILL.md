# 电商整套图片策划与生成

把产品照片和简短资料编译成一套可执行的电商视觉方案。先确认事实和发布环境，再围绕买家问题选择图片角色、编写逐图中文提示词，并在用户要求时使用 Codex 内置 `imagegen` 生成或编辑图片。

## 核心原则

1. 根据商品事实、买家问题、素材覆盖度和平台合同决定图片数量与角色。
2. 原始产品照片是商品身份、结构、颜色和包装文字的主要依据。
3. 可见事实、用户确认事实和可靠来源事实可以支撑确定性文案；观察不确定项与创意假设不能升级为产品承诺。
4. 每张图只承担一个主要沟通任务，人物、场景、道具、效果和文字共同支撑该任务。
5. 同一套图统一画幅和视觉系统；面向多个平台时分别输出完整套图计划。
6. 策划说明、生成提示词、负面约束和质量检查使用中文；图内文案服从目标市场；包装原文保持不变。
7. 精确参数、长文案和品牌级排版优先采用无字底图与确定性后期排版。
8. 任何可执行页面都必须绑定真实可用的原始参考；素材不支持的页面进入暂缓模块。

## 工作流

### 1. 确认任务范围

- 只需策划或提示词：完成计划、提示词和验证，不生成图片。
- 需要成图：先验证计划，再按优先级调用 Codex 内置 `imagegen`。
- 同时指定多个平台：先共享商品事实，再为每个平台建立独立计划，输出 `multi_set_manifest`。

缺少平台时，将任务记为 `portfolio`，按商品形态和展示用途选择画幅，并把判断来源标记为 `default`。不要把默认作品集冒充具体电商平台。

### 2. 检查全部原始素材

逐张查看原图，记录：

- 商品身份是否清晰
- 可见角度、结构、颜色和包装文字
- 遮挡、反光、分辨率和可裁切细节
- 可直接复用的部分
- 无法从现有素材确认的部分

不要仅凭文件名、品类常识或生成结果补全不可见结构。

### 3. 判断平台、市场与语言

读取 [平台与语言规则](references/platform-language-rules.md)。平台规则可能变化；声称强制要求前先查询目标站点的当前官方资料，并记录核验时间与来源。

分开记录：

- `planning_language`：`zh-CN`
- `prompt_language`：`zh-CN`
- `overlay_language`：目标市场语言
- `packaging_text_policy`：`preserve_original`

### 4. 建立事实账本与买家问题

把信息分成：

- 可见事实
- 用户确认事实
- 官方或可靠来源确认事实
- 不确定观察
- 缺失关键信息
- 创意假设

再列出买家需要回答的问题，例如商品是什么、核心价值是什么、如何使用、尺寸是否合适、细节是否可信、包装包含什么。

### 5. 选择图片角色

从主视觉、合规首图、卖点、参数、细节、材质、尺寸、包装清单、对比和使用场景中按需选择。合并信息重复的页面；把缺少证据或参考角度的页面放入 `deferred_modules`。

`recommended_image_count` 只统计当前可执行的 `shots`。如果仍有安全页面可做，只暂停受缺失事实影响的模块；只有商品身份本身无法锁定时才阻塞整个商品。

### 6. 编写逐图中文提示词

读取 [提示词与生成路由](references/prompt-generation-routing.md)。每张提示词按以下顺序写清：

1. 商品身份与原始参考约束
2. 本图唯一任务
3. 商品位置、占比、角度和视觉动线
4. 人物身份、动作与视线（适用时）
5. 场景、道具与可观察证据
6. 镜头、光线、色彩和品牌气质
7. 图内文案、字体方向和安全位置
8. 保真要求与禁止项

每个 `shots[]` 先填写非空 `reference_inputs`，再编写提示词。需要的角度或细节没有参考时，暂停该页面。

### 7. 输出并验证计划

读取 [规划输出合同](references/planning-contract.md)，输出可读中文摘要和严格 JSON。将 `<SKILL_DIR>` 替换为本 Skill 目录后运行：

```powershell
python <SKILL_DIR>/scripts/validate_plan.py <plan.json>
```

验证失败时修订计划；通过前不进入批量生成。

### 8. 生成、排版与验收

按照 `execution_action` 使用 Codex 内置 `imagegen` 生成或编辑。编辑商品图时始终附带原始产品参考；上一张生成图不能成为后续页面唯一的身份依据。

每完成一张就读取 [质量检查与失败恢复](references/qa-and-recovery.md)，按 `qa_checks` 验收。商品身份、结构、事实或平台合同错误属于致命失败；文字与参数优先转确定性排版修复。

## 默认交付物

- `content_plan.md`：平台、事实边界、视觉系统和逐图意图
- `image_set_plan.json`：可机检计划
- `prompts.md`：逐图中文提示词、图内准确文案和负面约束
- `outputs/`：用户要求生成时的图片
- `qa_report.md`：逐图状态、问题、修复和待补资料

## 暂停条件

只暂停受以下问题直接影响的页面：

- 商品身份或关键结构无法从原始参考确认
- 参数、功效、认证、成分或比较结论没有可靠来源
- 首图合同尚未核验
- 图内文案语言或包装原文处理存在冲突
- 页面同时承担多个无法清晰合并的购买理由
