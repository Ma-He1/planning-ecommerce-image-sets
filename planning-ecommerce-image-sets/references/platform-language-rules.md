# 平台、发布面与语言路由

## 使用顺序

1. 先确认发布面：商品详情页、商品主图、A+、店铺装修、图文笔记、短视频封面和广告素材是不同合同，不能混用。
2. 再确认平台、国家/地区、业务类型、店铺身份和类目。
3. 读取机器可检的 [平台图片规则库](platform-requirements.json)，选择最接近的 `platform_profile_id`。
4. 按规则库的 `verification_status` 决定是否需要登录商家后台复核。
5. 将已确认规则、创意建议和待复核项分别写入计划，不把经验或旧教程伪装成平台硬规则。

本地摘要只能帮助路由，不能单独证明平台要求。平台硬规则必须追溯到当前官方公开资料、可确认身份的官方员工公告或登录后的平台界面。用户提供的 `user_contract` 与 `project_contract` 可以增加项目约束，但不能放宽或覆盖平台官方硬规则。

## 规则分层

| 层级 | 可以写什么 | 不能写什么 |
|---|---|---|
| `hard_rules` | 当前官方资料明确要求的平台格式、尺寸、背景、禁限项，或项目合同额外增加且不与平台规则冲突的约束 | 转化经验、推荐尺寸、未核验的类目数字、用用户合同放宽平台规则 |
| `creative_guidance` | 构图、信息顺序、建议分辨率、场景和转化做法 | 伪装成“不满足就无法发布”的强制要求 |
| `publish_time_recheck` | 站点、类目、账号权限、模板和规则冲突等待查项目 | 已经确认的硬规则 |
| `conditional_rules` | 仅在明确条件成立时适用的规则 | 未确认条件就直接升级为整个平台规则 |

规则库状态与计划字段映射：

| 规则库状态 | 计划 `verification_status` | 处理方式 |
|---|---|---|
| `verified_public` | `verified_current` | 可引用公开官方规则；仍核对目标类目例外 |
| `partial_public` | `partially_verified` | 只采用已证实部分，必须保留发布前复核清单 |
| `live_check_required` | `live_check_required` | 通用 `hard_rules` 保持为空，在当前商家后台核验后再填 |
| 非平台作品集或项目合同 | `not_applicable` | 不冒充平台规则；使用项目合同或用户合同 |

`official_public_archive` 表示平台官方历史页面、旧课件或归档文档，只能作为 `partial_public` 的局部或历史证据，并且必须写入 `publish_time_recheck`；它不能单独把计划升级为 `verified_current`。用户合同不能覆盖内置画像。`live_platform_ui` 可以记录当前后台观察，但来源类型、域名和一段说明都不足以自动证明规则已经变化；如需改变画像状态、硬规则或首图合同，必须先复核证据并更新规则库与回归测试。

规则库中的 `machine_constraints` 只覆盖可稳定结构化判断的子集，例如总张数、发布槽位张数、首图角色和各槽位文字模式。若画像声明槽位约束，对应 `shots[]` 必须填写 `platform_slot`，避免把详情图和主轮播图混为一谈。脚本不会自动理解所有规则语义，也不会自动确认条件规则、类目例外、图片审美、商品真实性或 Amazon 逼真 AI 人物的 XMP 元数据；这些内容仍需人工和发布前 QA。

## 已内置的平台画像

| `platform_profile_id` | 发布面 | 当前证据状态 | 策划时最重要的区别 |
|---|---|---|---|
| `amazon-us-listing-images` | Amazon US 商品详情图 | 公开规则已核验，类目需复核 | 主图纯白、无新增文字；最长边 500–10000 px 是接受范围，1000 px 以上是缩放建议；逼真 AI 人物有需人工确认的 XMP 元数据条件规则 |
| `ebay-us-listing-images` | eBay US 刊登图 | 公开规则已核验 | 禁止新增文字、营销图形和水印适用于全部刊登图；不强制纯白背景 |
| `etsy-listing-images` | Etsy 商品图 | 公开规则已核验 | 不强制白底或固定比例；首图要为多种缩略图裁切留空间 |
| `walmart-us-listing-images` | Walmart US 商品详情图 | 公开规则已核验 | 主图纯白；2200 × 2200 是官方目标规格，1500 × 1500 是缩放阈值，不虚构更低尺寸的统一拒绝门槛 |
| `tiktok-shop-us-listing-images` | TikTok Shop US 商品详情图 | 公开规则已核验 | 主图白底；所有商品图禁止新增文字覆盖；1:1 是常规建议，3:4 至 4:3 只属于官方 Excel/bulk 上传路径的条件规则，不外推到所有入口 |
| `shopify-product-media` | Shopify 商品媒体 | 公开规则已核验，主题需复核 | 不强制白底或固定比例；上传上限与前台主题槽位分开，集合页首图可建议统一比例 |
| `shopee-marketplace-listing-images` | Shopee 商品详情图 | 公开资料仅部分覆盖 | 站点和 Mall/普通店合同不同，不把单一国家旧课件外推为全平台规则 |
| `lazada-marketplace-listing-images` | Lazada 商品详情图 | 公开资料仅部分覆盖 | Open Platform API 字段限制不等于 Seller Center 全部视觉规则 |
| `taobao-cn-listing-images` | 淘宝商品图 | 基础公开规则已核验，规格需后台复核 | 真实清晰、图文一致、禁止站外导流和 AI 实质性失真；类目和订购服务会改变图片槽位与规格 |
| `tmall-cn-listing-images` | 天猫商品图 | 公开资料仅部分覆盖 | 不把淘宝通用规则或天猫历史主图标准直接外推为当前天猫全平台合同；AI 商品失真禁限项可按当前公开资料使用，其余规格需后台复核 |
| `jd-cn-listing-images` | 京东商品图 | 基础公开规则已核验，规格需后台复核 | 首图售卖物与规格必须一致，禁止站外导流和擅用平台标志；自营、POP、全球购和类目合同不可混用 |
| `pinduoduo-cn-listing-images` | 拼多多商品图 | 基础公开规则已核验，规格需后台复核 | 主图背景以纯白为主；主轮播图禁新增文字、边框、角标、标签和水印；像素、比例、张数仍以后台为准 |
| `douyin-ecommerce-cn-listing-images` | 抖店商品详情图 | 通用公开规则已核验，规格需后台复核 | 首图为完整正面实物图，主图至少 3 张；除品牌标志外主图禁新增文字与水印；类目像素规则不能全平台外推 |
| `xiaohongshu-cn-product-images` | 小红书商品详情图 | 必须后台复核 | 商品 SPL ITEM、图文笔记封面、店铺装修和广告是不同发布面；旧开放平台 API 尺寸只能作条件规则 |

详细数字、适用角色、条件规则、来源 URL 和核验日期以 `platform-requirements.json` 为唯一内置数据源。表中“已核验”仅表示记录的公开通用规则有来源，不表示目标类目或发布时点已自动通过。

## 平台类型

- `amazon`：Amazon 站点商品详情图。
- `global_marketplace`：eBay、Etsy、Walmart、Shopee、Lazada 等跨境或海外市场。
- `domestic_marketplace`：淘宝/天猫、京东、拼多多等国内货架电商。
- `social_commerce`：TikTok Shop、抖音电商、小红书等社交电商的明确发布面。
- `brand_site`：品牌官网组件槽位；规则库已有该官网画像时仍必须绑定对应 registry，未知官网才使用明确的项目合同。
- `portfolio`：作品集展示，不代表真实平台发布合同。
- `custom`：用户提供尺寸、模板、安全区和交付格式的自定义合同。

同一商品面向多个平台时，分别建立完整计划。不能用 Amazon 白底首图规则覆盖 Etsy，也不能把抖店商品详情图的合同套到短视频封面。自定义项目使用 `verification_status: "not_applicable"` 时仍可在 `hard_rules` 中记录项目模板、安全区和交付格式；`not_applicable` 只表示不适用市场平台核验，不表示“没有项目硬规则”。

## 语言分层

| 层级 | 策略 |
|---|---|
| 策划说明 | 简体中文 `zh-CN` |
| 生成提示词 | 简体中文 `zh-CN` |
| 图内新增文案 | 用户指定或目标市场语言 |
| 包装、瓶身、铭牌原文 | `preserve_original` |

市场语言只能作为默认推断，用户指定优先。精确文字、多行文字、复杂字符集和法律敏感表述优先使用 `post_layout`。

## 字体与排版

- 根据品牌气质与目标语言选择字形，不把某一种黑体作为全品类默认。
- 先确定标题、数据、说明和角标层级，再决定字号、对齐和位置。
- 为文字预留安全区，不遮挡商品结构、合规标签或使用动作。
- 若平台禁止新增文字，整张图的 `text_strategy.mode` 使用 `none`，而不是只清空标题。
- 确保目标语言字库完整、字符正确、数字与单位清晰。
